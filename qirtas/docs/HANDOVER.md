# دليل التسليم والتشغيل — منصة قِرطاس

> أُعدّ في 2026-09-21. هذا الدليل للتشغيل والصيانة. تفاصيل الاستضافة والدفع موثّقة هنا فقط ولا تُذكر في الموقع العام.

## 1) ما الذي يعمل الآن

| المكوّن | الحالة | المكان |
|---|---|---|
| الموقع الثابت (‏848 صفحة) | مبني ومُختبر | `qirtas/site/dist/` |
| خادم التطبيق (API + لوحة التحكم) | يعمل على `http://localhost:8081` | `qirtas/server.js` |
| قاعدة البيانات SQLite | ‏419 كتابًا + جداول الطلبات والسجلات | `qirtas/data/qirtas.db` |
| لوحة التحكم | دخول محمي + كتب + طلبات + جذب + تدقيق | `/admin/` |
| نظام طلبات الإزالة | نموذج عام → قاعدة بيانات → مراجعة → قرار مسجَّل | `/rights/` + `/admin/requests` |
| خط المحتوى (جذب) | جوتنبرج + ويكي مصدر عربي/إنجليزي + كتالوج خارجي | `qirtas/pipeline/` |
| التطبيق (PWA + أندرويد) | مربوط بنفس الكتالوج بتحميل كسول | `reading-app-mvp/` |

## 2) أوامر اليومية

```bash
npm start                    # تشغيل كل شيء على 8081
npm run site:build           # إعادة بناء الموقع بعد أي تعديل بيانات
npm run db:verify            # فحص صحة قاعدة البيانات والتغطية
npm run test:smoke           # فحص HTTP شامل (44 فحصًا)
npm run test:widths          # فحص المقاسات (هاتف/تابلت/حاسوب) + لقطات
npm run test:ui              # فحص تفاعلي كامل (بحث، قارئ، مسارات خطأ)
```

## 3) لوحة التحكم (للمالك فقط)

- الرابط: `http://localhost:8081/admin/`
- كلمة المرور: تُولَّد عند أول تشغيل في `data/admin-password.txt` (ولا تُنشر على الموقع العام أبدًا). لتغييرها: `ADMIN_PASSWORD=كلمة-جديدة` قبل التشغيل.
- الجلسة: كوكي موقّع (HttpOnly) لمدة 12 ساعة. كل دخول فاشل يُسجَّل في سجل التدقيق.
- الإجراءات: إخفاء/إظهار، إزالة/استرجاع، وحلّ طلبات الإزالة بحالة + ملاحظة قرار.
- أي إجراء يُكتب في `audit_log` (الفاعل، الوقت، الإجراء، الهدف، التفاصيل).

## 4) دورة طلب إزالة حقوق النشر

1. صاحب الحق يفتح `‎/rights/` (أو زر «صاحب حق؟» في صفحة أي كتاب) ويملأ النموذج.
2. الطلب يُسجَّل في قاعدة البيانات بحالة `pending` + عنوان IP + وقت.
3. تراجعه في `/admin/requests` وتختار: `reviewing` / `removed` / `kept` + ملاحظة قرار.
4. اختيار `removed` يزيل الكتاب فورًا من قاعدة البيانات وبالتالي من البحث وصفحاته بعد `site:build`.
5. القرار والوقت والفاعل يُسجَّلان دائمًا في `audit_log`.

## 5) النسخ الاحتياطي والاسترجاع والتراجع (مُختبرة مرة واحدة)

```bash
npm run backup:create          # نسخة كاملة (DB + كتالوج + فهرس + كتالوج خارجي)
npm run backup:list            # عرض النسخ
npm run backup:restore -- <اسم-النسخة>   # يسترجع (ويعمل نسخة أمان قبلها)
```
- مُختبر: `backup:create delivery-test` ثم `restore` ثم تحقق بـ `db:verify` (‏419 كتابًا كما هي).
- **تراجع الكود:** مجلد `.backup-2026-09-21/` يحتوي نسخ الملفات الأصلية، وكل إصدار له commit في Git (ارجع بـ `git revert` أو `git checkout <sha>`).

## 6) معالجة الأخطاء والحدود (مكتوبة ومُختبرة)

| الحالة | السلوك | الدليل |
|---|---|---|
| مصدر ميت أو رابط مكسور | الجذب يُسجّل الفشل ويستمر بالبقية؛ الكتاب يبقى بسجل كامل + رابط أصلي | `cache/*-failures.json` + `import_runs` |
| نص مفقود عند البناء | تحذير صريح ولا يُكسر البناء | `⚠ no text for <id>` |
| كتاب مفقود في القارئ | واجهة خطأ عربية + زر إعادة محاولة + رابط صفحة الكتاب | فحص `reader.network_failure` |
| بحث بلا نتائج | حالة «لا نتائج» + إعادة ضبط + اقتراح توسيع البحث | فحص `library.empty_state` |
| انقطاع الشبكة في القارئ | رسالة + إعادة محاولة؛ الموضع محفوظ محليًا | `sw.js` + `reader.js` |
| تعذّر تحميل الكتالوج الخارجي | رسالة + زر إعادة المحاولة | `library.js` |
| عدم وجود أغلفة صورية | أغلفة مولّدة من الهوية (تدرّجات) لكل كتاب | `.cover` |
| مسار غير موجود | صفحة 404 كاملة فيها بحث وروابط | فحص `server.404_page` |
| حجب طلبات API من مصدر | المصدر يُعلَّم في سجل التدقيق الحقوقي ولا يُلحَح | `docs/SOURCES-AUDIT.md` |

## 7) الأداء وتجربة القراءة

- بنية ثابتة: كل صفحة HTML جاهزة مسبقًا (أسرع من العرض الديناميكي).
- البحث في المتصفح على فهرس خفيف (‏164KB) مع تطبيع عربي (تشكيل/همزات/تاء مربوطة).
- القارئ: ترقيم أفقي، خط نسخ محلي (‏بلا تحميل خارجي)، افتراضي حجم لكل جهاز (هاتف 1.0×، تابلت 1.08×، حاسوب 1.14×)، وضع ليلي/نهاري، تبديل خط النظام/النسخ، مناطق لمس للتقليب، اختصارات لوحة المفاتيح (F للخط، D للتنزيل).
- تنزيل EPUB لكل كتاب (يُبنى فوريًا) + طباعة/حفظ PDF بتنسيق مخصّص للطباعة.
- القراءة دون إنترنت: Service Worker يخزّن الهيكل والنصوص بعد أول زيارة.

1. أخبرني «جاهز» وسأفتح المتصفح على `github.com/login`.
2. **أنت** تكتب البريد `iteih67@gmail.com` وكلمة المرور ورمز التحقق — أنا لا أدخلها ولا أخزّنها.
3. بعد الدخول أُنشئ مستودعًا باسم `qirtas` وأربطه محليًا وأدفع الكود (‏~250MB تشمل نصوص الكتب).

## تحديثات الاستكمال (جولة ما بعد التسليم الأول)

### 1) تصفّح حسب المؤلف والحقبة الزمنية (سدّ فجوة معايير القبول)
- صفحات مؤلف: `site/dist/author/<slug>/` — **289 صفحة**، وفهرس `/authors/`.
- صفحات حقبة زمنية: `site/dist/era/<slug>/` — **4 صفحات** (تراث عربي، القرن التاسع عشر، القرن العشرون، كلاسيكيات عالمية).
- مرشّح الحقبة في صفحة المكتبة (`?era=`) مع بقاء الحالة في الرابط.

### 2) تنزيل EPUB يعمل على الاستضافة الثابتة
قبل: كان EPUB يُولَّد عند الطلب من `server.js` فقط (`/api/book/<id>.epub`) — أي أنه لا يعمل على GitHub Pages.
الآن: `node site/tools/build-epub.js` ينتج `site/dist/download/<id>.epub` لكل الكتب (**419 ملفًا، 239.6MB**، أصغر 10.7KB، أكبر 5.4MB)، وروابط الصفحات صارت `/download/<id>.epub` — تعمل على المنصة الثابتة وعلى الخادم المحلي.
لتقليل حجم النشر يمكن تعطيل هذه الخطوة في سير العمل (workflow) — البحث يبقى كاملًا.
